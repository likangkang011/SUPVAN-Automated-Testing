## 目录结构说明
| 目录名             | 核心作用               |
|-----------------|--------------------|
| `config/`       | 项目配置中心（设备、定位、环境）   |
| `data/`         | 测试数据存储（JSON/Excel） |
| `logs/`         | 自动生成的测试日志          |
| `reports/`      | 自动生成的测试报告          |
| `page_objects/` | 页面对象封装（POM 核心）     |
| `reports/`      | 自动生成的测试报告（HTML）    |
| `requirements/` | 依赖清单               |
| `Test/`         | 测试代码存放的文件夹         |
| `testcases/`    | 测试用例集（按功能模块划分）     |
| `utils/`        | 通用工具类（驱动、日志、断言）    |
| `tools/`        | 一次性/辅助脚本（控件树抓取、定位生成） |

## 找元素定位

按场景选工具：

| 场景 | 用什么 |
| --- | --- |
| 手机就在手边，想知道「屏幕上这个东西」该怎么定位 | GUI 顶部 **元素拾取**：点截图即出 |
| 想知道 `locators.py` 里已有的定位是不是坏/重复/没人用 | GUI 顶部 **元素定位**：纯静态体检，不连设备 |
| 想把整个 App 的控件树一次性扒下来 | `python tools/ui_tree_dump.py all` |

### 元素拾取（推荐日常用）

前提：Appium 已启动、设备已连（主界面「环境状态」为绿）。

1. 点顶部 **元素拾取** → **连接设备**（首次建会话要几十秒）
2. 抓到的这一屏显示在左侧，**鼠标点截图上的任意位置**
3. 右侧自动给：控件属性、当前屏是否唯一、以及可复制的定位代码
4. 元素在下一屏？点 **上滑 / 下滑 / 返回 / 拉起 App** 后自动重新抓取

定位策略按可靠度排序，列表里只会给出当前控件真正可用的那几条：

| 策略 | 说明 |
| --- | --- |
| `resource-id` | 全局唯一时最稳，首选 |
| `resource-id + 文案` | 同 id 多实例（宫格、列表）时用文案收窄 |
| `祖先 id + 文案 / 类名` | 控件本身没 id 时的相对路径，抗层级变动 |
| `文本` | 无 id 时的备选，文案改了会失效（标黄提示） |
| `class 绝对路径` | 兜底，页面结构一变就废（标红） |
| `坐标比例` | 实在没有可定位属性时，配 `COORDINATE` + `tap_ratio` 盲点 |

点了控件但想选外层按钮？点 **↑ 选父级**。

### 边界

- 只认**当前这一屏**，不猜页面路径；页面要自己滑/退到位。
- 唯一性只在当前屏校验 —— 这是离线能确定的最大范围。
- 工具**不写** `locators.py`，只生成代码，粘不粘由你定。
- 控件如果已被收录（按 resource-id 比对），会直接告诉你原 key，避免在库里造重复别名。
